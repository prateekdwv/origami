# Nationwide timetable collection — 15 October 2026

This is a **schedule-data collection**, not recorded operations, an animation,
or a certified list of every train that operated on the date. Passenger services
include suburban/local trains. Freight and independent metro systems are outside
the requested scope. No train-count or major-city sampling is applied.

## Files

- `sources/`: pinned public snapshots and their upstream notices. Compressed JSON
  sources retain every original field. `gtfs.zip` is retained unchanged.
- `trains.json.gz`: one normalized timetable per available train number, with all
  retained stops, scheduled arrival/departure offsets, operating weekdays, source,
  and service-calendar bounds where available. Times are seconds since midnight
  of the origin's service date; values above 86,400 indicate later journey days.
- `stations.json.gz`: station directory, names and available coordinates.
- `journeys-2026-10-15.json.gz`: projected journey instances overlapping
  00:00–24:00 IST, including departures on preceding days. Records reference the
  master timetable by train number; clipped window bounds are seconds into the
  target day. `date_certified` is false throughout.
- `journeys-2026-10-15.csv`: the same main projection as a readable table, with
  train numbers, names, types, endpoints, origin dates and ISO 8601 scheduled
  departure/arrival timestamps including the `+05:30` offset.
- `review-only-journeys-2026-10-15.json.gz`: projections from additional-only,
  undated records, kept separate because they could be obsolete or renumbered.
- `coverage.json`: counts, types, hourly activity, conflicting source records,
  excluded freight, rejected schedules, absent target-day candidates and limitations.
- `provenance.json`: immutable source URLs, stored-file hashes, timestamps and
  licensing notes. Read upstream notices before publishing the collected assets.

JSON gzip files can be read with Python's standard library:

```python
import gzip, json
with gzip.open("projects/india_railway_2026/assets/schedules/trains.json.gz", "rt", encoding="utf-8") as source:
    trains = json.load(source)
```

## Sources and selection

The primary GTFS snapshot is from [Neo2308/indianrailways-gtfs](https://github.com/Neo2308/indianrailways-gtfs),
commit `b340b7048e99c18330ad333e8210d61161ac7a43` (10,594 trip records).
Its publisher-wide date range ends on **30 September 2026**. Individual service
calendars often extend beyond that, but the feed cannot certify 15 October.
Some referenced service calendars are missing; these records are rejected rather
than assigned invented running days. No explicit redistribution license was
found; retaining the public data does not assert new rights over it.

The second snapshot is from [shwetankg07/RailRaag](https://github.com/shwetankg07/RailRaag),
commit `656f4d7db73d9d89ef2393377bd29987940d2cbc` (9,298 compiled timetables).
Its build code describes an NTES crawl, while its data license notice describes
CC0 DataMeet-derived schedules. This provenance inconsistency is recorded, not
resolved by applying the code's MIT license to all upstream data. The binary
contains weekday masks, not exact operating dates. Its builder defaults missing
run dates to daily and drops some stations/trains, so these masks are provisional.
Its `Premium Express` label maps upstream `PEXP` parcel services; these train
numbers are excluded from the passenger selection.

The supplemental snapshot is from [prasenjit-27/Indian-Railway-Data](https://github.com/prasenjit-27/Indian-Railway-Data),
commit `1dc0ddbc6a06b09ef69d4825ff3127c1f29640fa` (5,208 records, supplied under
MIT). It has weekday flags but no effective-date ranges. Additional-only train
numbers are retained in the master and review projection, not silently mixed
into the main target-day projection.

For overlapping valid records, prefer GTFS, then RailRaag, then the additional
snapshot. Never join stops from conflicting versions of a timetable. Source
disagreements are listed for review. Invalid chronology, missing timetables,
invalid operating days, and passenger durations exceeding seven days are
quarantined; the original source records remain available.

## Reproduce without rendering

```powershell
# Rebuild only from the retained local snapshots:
uv run python projects/india_railway_2026/collect_schedules.py --date 2026-10-15
# Download missing immutable source files, then rebuild:
uv run python projects/india_railway_2026/collect_schedules.py --date 2026-10-15 --download
```

No RailRadar or RailKit key is needed. No rendering modules are imported and no
video is generated by collection. The real-observation loader remains separate.
Timetable revisions, special services, historical
cancellations and national completeness remain unverified.
